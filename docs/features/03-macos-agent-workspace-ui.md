## 1. 参考基线与复用方式

Lyre 当前工作区的改版已经写入 `apps/macos/Lyre/Views`，包含单窗口导航、列表详情、设置和隔离预览；这些改动尚未提交，不能把它们全部归到 `47d8807`。Showtime 参考 `25a7d6e` 的实际源码。原生预览的[来源记录](../design/macos-agent-workspace/SOURCES.md)保存所用文件的 SHA-256，便于复查。

Otter 沿用 Lyre 的资料库布局和状态组织，借用 Showtime 的 Inspector、原生菜单与窗口测试方式。小控件直接复制到 Otter 后改名、换色、适配语义；不建立跨三个仓库的 UI 包，也不让发行版依赖相邻 checkout。

## 2. 窗口与信息层级

主窗口是工作台，菜单栏可选地显示扫描/备份状态并返回同一窗口。Settings 与 About 也在此窗口内，`⌘,` 进入 Settings；独立文件比较/编辑窗口按用户动作打开。主窗口关闭后，草稿和任务属于应用会话，不由 View 的 `onDisappear` 取消。

尺寸指内容布局的 pt，系统标题栏会增加外框高度。默认 1280 × 800，最低 1000 × 680，首次打开按屏幕可用区域限制；超出屏幕时优先降低初始尺寸。窗口恢复先验证屏幕仍存在，避免记住已经拔掉的外接显示器位置。

| 区域 | 建议尺寸 | 行为 |
| --- | --- | --- |
| 主导航 | 默认 212，目标范围 192–248 | 一个原生 `NavigationSplitView`；支持系统侧栏按钮与 `⌃⌘S` |
| 库列表 | 工作区中的主要 `Table` / `List` | Skills、Agents、任务各自保存排序、筛选和选择；多选时展示共同操作和混合值 |
| 包文件树 | 默认 200，目标范围 160–280 | 进入编辑时替代库列表，顶部有“返回 Skills”；目录可展开，长路径居中省略并可复制完整路径 |
| 编辑内容 | 优先保证至少 480 | 空间不足时先收起 Inspector；两份文档的并排编辑不足 800 时保留标签，停止强行并排 |
| Inspector | 默认 280，目标范围 260–360 | `⌥⌘I` 切换；临时窄窗口收起不清空用户的宽窗口偏好和选中分组 |
| 正文页边距 | 页面与弹窗 24；卡片与编辑子面板 16 | 表格外框与筛选行两端对齐；长表单和长正文局部滚动 |
| 页内主要控件 | 32 高；图标按钮 32 × 32 | 表格内辅助按钮可用系统 small control；选中态不能只靠颜色 |
| 行与标题 | 库行随两行内容；文件树 30；标题 23 / 14 | 正文 13，说明 12，状态与代码说明 11；源码编辑字号独立可调 |
| 底栏 | 28–32 | 索引状态、选中数量、当前任务；编辑区另有文件格式/保存状态 |

实际 App 的文字角色集中在 `apps/macos/Otter/Controls.swift` 的 `OtterTypography`。页面与弹窗共用标题，Agent/CLI 卡片与 Inspector 共用分组标题，正文、次要信息和状态各用固定字号；品牌字、统计数字和 SF Symbol 尺寸单独处理。侧栏选中和分段切换不改变字体几何。

设置与创建/替换表单用原生 `Grid` 共享标签列。单行输入、搜索、菜单、分段选择器与按钮采用同一控件高度；多行输入按内容增高。输入框保留原生文字输入与可见焦点边框，空状态共用小标题和说明样式。

只使用一层原生导航分栏。Lyre 已遇到 macOS 26 中嵌套分栏重复计算 sidebar 安全区的问题，因此内部工作区先按其 `HStack + Divider` 方式组织，并检验实际 content bounds；需要拖动的内部栏使用独立、受约束的分栏实现后再验收。当前原生预览演示固定内部栏宽和自动收起，尚不证明可拖动栏宽已实现。

原型的紧凑布局根据**实际可用工作区宽度**判断，而不根据显示器分辨率猜测。`工作区 < 980` 时收起侧边 Inspector，手动打开时用系统 popover；编辑区保留文件树与正文。焦点和未保存内容必须在布局变化后保留。

工具栏的上下文菜单位于工作区左侧，搜索与扫描位于右侧，隐藏重复产品名。Inspector 入口随资源出现在库标题或编辑工具栏；保存/分发只在编辑区出现，登录/上传只在任务流程出现。扫描按钮的空闲、进行中、停止中保持固定外框；只有 collector 提供真实计数时才显示完成数或进度。

## 3. 每个页面的控件与操作

| 页面 | 默认内容 | 选择后呈现 | 主要动作与下一步 |
| --- | --- | --- | --- |
| 概览 | 简洁的最近扫描摘要；需处理问题按影响分组；最近操作 | 问题 Inspector：事实、期望依据、链接链、影响与证据时间 | “查看差异”/“验证发现”进入相应页面；不提供缺乏明确定义的健康分数 |
| Agents | 原生表格：名称、CLI 版本/未定位、配置、问题数 | 指令、commands、skills、hooks、配置入口；Hermes 显式 profile 切换 | “打开配置”“验证发现”；切换 cwd/profile 后旧观测显示“属于上次上下文”，不伪装成最新结果 |
| 指令与命令 | 顶部系统 segmented picker：指令 / Commands / Rules / Hooks；左侧入口列表 | 正文只读预览/编辑；Inspector 中显示加载顺序和链接关系 | 编辑、比较、预览同步；Claude CLAUDE.md 与全局 Workflow 源的关系写在保存栏 |
| Skills 库 | Table：名称、来源、关系、发现状态、问题；搜索与来源/harness 筛选 | 包概要、所有入口、上游状态和校验结果 | 双击或 Return 编辑；Space Quick Look；多选仅提供共同支持的分发/导出动作 |
| Skills 编辑 | 包文件树、多标签、源码/预览/分栏、Problems | Inspector 分“元数据 / 使用方 / 历史”；选择问题定位文件行列 | `⌘S` 保存源；“预览分发…”审阅目标；保存路径和影响始终可见 |
| Workflow | 默认是可排序绑定表；选中项旁显示源 → 入口 → 消费方 | 实线代表实时共享，虚线代表受管理副本，未认领关系有文字说明 | 比较、更新副本、修复单个链接、暂停绑定；图中的每个节点都有等价列表入口 |
| 备份与任务 | 快照列表和活动任务；覆盖范围、部分失败与缺项 | 选定快照的内容预览；按阶段显示结果和下一步 | 扫描 → 保存快照 → 审阅上传；正在运行的任务跨页面保留，可回到相同任务 |
| Settings | 原生分段页：通用 / 来源与扫描 / 编辑器 / CLI 与备份 | 当前设置的解释与实际路径、可执行版本、目标 host | 选择目录、切换 CLI、显式安装命令行入口；连接可达与已认证分开显示 |

页面筛选属于当前页，`⌘K` 才是跨资源搜索。搜索结果每行显示资源类型、所在 scope、来源和关系；同名 skill 按源区分，不合并。`⌘F` 在库页聚焦筛选框，在编辑器内查找正文；`⇧⌘F` 搜索当前包。Escape 按层关闭菜单、popover、搜索、sheet，不清除草稿。

选择、焦点和正在编辑的文档是三个独立状态。扫描或排序后仍能找到同一资源时保持选择；选中项消失时在详情说明原因，不能把新选中项的内容塞进旧的编辑 buffer。切换到 Settings 再返回时，标签、插入点、搜索、Problems 与任务进度均保留。

## 4. 编辑器的关键细节

编辑顶部的定位信息分三层：包名与来源；当前文件标签；保存目标与已知使用方。一个醒目的 `实时共享` 标签不足以说明影响，因此保存栏显示“写入 Workflow 源文件 · 3 个入口共享”，同时区分另有副本需要同步。

文件树的目录层级和标签都使用稳定的文档身份。dirty 点有“未保存”可访问描述；失效链接显示坏掉的一跳；外部链接用可展开的解释而不静默展开到未知目录。`SKILL.md`、`agents/openai.yaml`、脚本与 references 都走同一 buffer/撤销/外部变更处理流程。

格式问题放在正文下方可伸缩的 Problems 区，严重度、文件、行列、规则来源一行可读。Inspector 的元数据表单只是同一 buffer 的另一种编辑入口。点击 Quick Fix 先展示修改，应用后留在该文件与问题位置；不能因一次表单操作重建文本视图、重置中文输入或覆盖未知 YAML 字段。

原生 `NSTextView` / TextKit 承担文本输入、选择、撤销、系统查找与服务菜单。仅在 buffer 真的外部变化时更新 `textStorage`；不在每个 SwiftUI update 里重设全文。语法高亮与校验异步，回包带文档 revision，标记文本期间不强行重排。预览字体、主题和滚动分开维护，不把源码当富文本保存。

| 编辑状态 | 永久可见的信息 | 可用动作 |
| --- | --- | --- |
| 干净 | 已保存到具体路径、上次校验范围 | 编辑、比较、预览分发 |
| 未保存 | 标签 dirty 点、草稿状态、保存影响 | 保存源、放弃当前文档的修改、继续编辑 |
| 必需格式错误 | Problems 定位、草稿保留、尚未写入源 | 修复；当前受消费源的保存/分发禁用并给原因 |
| 外部冲突 | 磁盘已变化、自己的草稿仍在 | 查看磁盘、双栏或有基线的三方合并；不以普通 Cmd-S 覆盖 |
| 源只读/失联 | 具体路径与读写错误 | 重试、另存为独立包、保留草稿 |
| 保存/同步中 | 目标、阶段、当前执行项 | 阻止重复提交；切页保留状态；按实际可取消边界提供取消 |

Cmd-S 是保存真实目标。预览中的文本编辑只改变示例内存，按钮必须明确写“保存示例”，不得把它当作生产保存实现；完整编辑器的交付范围仍以主设计第 5 节为准。

## 5. 变更预览与反馈

采用原生 sheet，宽度约 760，紧凑屏幕不超过父窗口可用宽度。标题写具体动作，例如“更新 Codex 指令副本”；顶部列源、目标、绑定方式、受影响入口和观测版本，中部展示逐文件差异，底部固定“取消”“应用 2 项变更”。副作用和无法验证的项目在提交按钮附近，不藏进原始日志。

默认折叠未改变文件，删除、覆盖、解除链接分别用动作文字标明。文本差异支持行内/并排；没有基线时明确“只有两个当前版本”，不显示虚构祖先。建立链接与更新内容是两个变更项，可以分别关闭；必需的依赖需要一并选中并解释。

应用后 sheet 进入结果状态：逐项成功/失败/跳过、已检查的文件状态、独立的运行时发现结果。可返回任务记录、查看源、按条件撤销。取消预览不写文件；应用过程中退出不声称已撤销，记录实际完成项。再次应用前重新检查 hash/链接链，过期预览回到差异确认。

轻量“已复制路径”或“已保存”可沿用 Showtime Toast；鼠标悬停/键盘焦点时暂停消失。用户需要决定的冲突与失败留在原位，旁边始终有重试/查看详情。Reduce Motion 时关闭位移/缩放，仅保留必要的状态变化；Reduce Transparency 时原生导航使用系统提供的实体回退。

## 6. CLI 与设置的原生体验

借用 Lyre 详情底部操作栏和跨页后台上传入口：任务在进行时，侧栏底部出现简短状态；点击回到其任务详情。结果页先展示快照、覆盖范围和失败项，原始命令/stdout/stderr 放在可展开的“诊断”区域。无计数的阶段用不定进度条，已收到 collector 结果时才显示例如“完成 8 / 13”。

保存快照与上传是两个明确阶段。上传页显示固定的 snapshot ID、实际 API host、账号状态、文件清单/正文的区别，以及 slim 的真实范围；不能把“已备份”用于仅仅扫描完成的状态。部分失败允许用户查看缺项后选择后续动作，保留上传结果未知的状态。

Settings 使用 Lyre 的单窗口分段组织和两列对齐表单。来源路径支持系统目录选择器；GUI 默认使用内置 CLI，外部选择显示真实路径/版本/兼容性。安装稳定命令行入口是显式按钮，安装后再显示可复制命令。路径选择不读取 shell rc，认证状态不把 token 展示成普通文本字段。

## 7. 体验验收如何落地

Lyre 的预览模式用于设计回归，Showtime 的真实输入用于交互回归，两者分别出证据。截图中的数据可以由 fixture 设置，但点击、键盘和磁盘结果不能只靠 model setter 证明。

| 验收 | 输入与检查 |
| --- | --- |
| 原生窗口 | 实际红黄绿可见；缩放/还原/最小化/全屏遵循系统；只在首次启动放置；切外观和 Inspector 不重置窗口 |
| 分栏与滚动 | 1280 × 800 / 1000 × 680；Inspector 自动收起可访问；正文不被遮挡；长路径、30 个标签、500 条结果可滚动 |
| 键盘 | Tab / Shift-Tab / 方向键 / Cmd 多选 / Enter / Space / Escape；菜单和 toolbar 的同名动作走同一 command；不抢占输入法标记文本 |
| 状态保留 | 编辑后切 Settings、切 profile、扫描、缩窗再返回；草稿、光标、选择和活动任务仍正确 |
| 保存与格式 | 中文输入、撤销、CRLF/注释/未知 metadata 无损；Problems 可跳转；未通过必需校验不能显示已写入源 |
